# weekly 周边界：周一起始，凌晨 4 点对齐

> **状态：已决定（weekly 查询与聚合实现范围内）。** 本文落定周窗口的时间语义，
> 负责模块 weekly（周边界函数归 timeline 的 time 能力，实现在 `internal/timeutil`）。
> 截止时机为「周聚合与 `GetWeeklyDashboard` 绑定实现前」——即本次打通。

## 1. 决定

| 决策点 | 决定 |
|---|---|
| 周起始 | **周一** |
| 对齐方式 | 按凌晨 4 点**逻辑日**对齐：周窗口 = `[周一 04:00, 下周一 04:00)`（本地时区） |
| 所属周 | 某时刻所属周 = 其逻辑日日期所在的自然周（周一~周日） |
| `weekStart` | 该周周一的 `yyyy-MM-dd` |

推论：**周日凌晨 00:00–04:00 的活动逻辑日是周六，归上一周。** 这是对齐 4 点边界的
直接结果，与 `GetDayContext` / 卡片 `day` 的语义一致，不是特例。

## 2. 依据

| 考虑 | 说明 |
|---|---|
| 测试口径 | 08 §8.6.4 与 09 §9.4 G-stability 的长期观察均以「跨一个周一」为验收窗口，周一为界使「跨周」事件恰好落在窗口边界上，观察与实现一致 |
| 用户习惯 | 周报心智是「本周（周一起）到现在」，周一为界符合中文语境的工作周期 |
| 单一边界来源 | 日界与周边界都由 `internal/timeutil` 从同一个 `BoundaryHour = 4` 派生，前端与调用方不自算（03 §3.2「day 只能由 timeutil 生成」） |

## 3. 候选与取舍

### 3.1 选中：周一 + 4 点逻辑日对齐

见上表。

### 3.2 未选中：周日起始（美式习惯）

`weekStart` 会落在多数用户工作周期的中间，「本周已过半」的首屏观感差；与 08 的
「跨周一」观察口径也不一致。

### 3.3 未选中：日历日（午夜）对齐

会产生与逻辑日双轨的日期归属：同一张卡片可能 `day` 在上一周、周聚合却算在下一周。
日界语义只能有一套。

## 4. 实现要点

- `timeutil.WeekStart(day, loc)`：`day` 是逻辑日，返回其所在周的周一 `yyyy-MM-dd`；
  `timeutil.WeekWindow(weekStart, loc)` 返回左闭右开的 `[周一 04:00, 下周一 04:00)`。
- `GetWeeklyDashboard(weekStart)` 的聚合窗口即 `WeekWindow`；卡片归属按重叠谓词
  （03 §3.5，与 `TotalMinutesTracked` 同一 SQL 谓词），不裁剪跨界卡片时长。
- `GetDayContext` 返回 `weekStart`，前端周导航永远传显式 `weekStart`，不自行推算
  （前端禁自算日界/周边界是硬规则）。
- 属性测试口径：连续 `weekStart` 的窗口无重叠、无间隙地拼接覆盖整时间轴（08 §8.6.4）。

## 6. 回退

周边界只是 `timeutil` 内两个纯函数的常量（起始 weekday + 复用 `BoundaryHour`）。
改为周日起始是函数内一行改动 + 夹具更新，不涉及 schema、DTO 或既有数据——历史卡片
按查询窗口聚合，窗口变了重新查询即得新归属，无迁移。
