# data 损坏恢复：自动从最新备份还原

> **状态：已决定（db-core / 维护实现范围内）。** `05 §5.6.2` 规则 5 要求
> `SQLITE_CORRUPT` / `SQLITE_NOTADB` 走「打开并恢复」路径，DB-7 断言「截断的库触发备份恢复」，
> 但两处都只规定**要恢复**，未规定**怎么恢复**。本文补齐流程、边界与回退。

## 1. 决定

写入实例打开数据库时，若连接因**损坏**失败，自动用 `backups/` 中**最新**的一份覆盖，
然后重试一次连接。

| 情形 | 行为 |
|---|---|
| 连接失败且归类为损坏，有备份 | 保留原库 → 还原最新备份 → 重试连接一次 → 记录恢复来源 |
| 连接失败且归类为损坏，无备份 | 报损坏错误，**不碰任何文件** |
| 连接失败但归类为**环境故障** | 报错误，**不碰任何文件** |
| 恢复后重试仍失败 | 报错误，两个文件都留在磁盘上 |
| 只读实例 | **不恢复**：它没有写锁，文件可能正被另一进程使用 |

## 2. 为什么是自动的

`05 §5.6.2` 规则 5 的措辞是「走打开并恢复**路径**」，DB-7 是「截断的库**触发**备份恢复」——
两处都要求恢复由打开动作触发，而不是等人手动执行。沉默地停在一个打不开的数据库前，
对用户没有任何补救价值。

**曾有的反对意见**（记录在此以免重复讨论）：`RestoreFromBackup` 早期注释称「恢复与 git revert
同属不可逆动作，应由人显式调用」。那条推理把两件事混为一谈——**schema 降级**确实不可逆，
而**损坏恢复**有明确的目标状态（备份），且原库被保留而非删除。文档要求的是后者自动触发。

## 3. 为什么必须区分损坏与环境故障

`05 §5.6.2` 规则 5 的括号写得直白：「磁盘环境错误不得触发恢复流程（**否则会销毁完好文件**）」。

磁盘满、目录不可写、权限不足时，数据库本身是完好的，只是写不进去。此时若走恢复，
会把一个健康但暂时不可写的库替换成旧备份——**用一次环境故障换来一次真实的数据损失**。

实现上这条边界由 `IsCorrupt` 保证：只有 `KindCorrupt` 允许恢复，其余（`KindEnvironment`、
`KindBusy`、`KindReadOnly`）一律拒绝。`Recoverable()` 只对 `KindCorrupt` 返回 true。

## 4. 保留而不删除

`docs/modules/data.md` 的回退一节：「故障先停止写入、**保留原库与备份**」。

所以恢复过程中**不删除任何文件**：

- 损坏的原库改名为 `<db>.replaced`；
- 若该名字已被占用（第二次恢复），追加序号 `<db>.replaced.2`、`.3`……**不覆盖**。
  固定名字会让第二次恢复静默丢弃第一份损坏样本，而那份样本是排查的唯一证据；
- 与旧库同属的 `-wal` / `-shm` 被删除，否则还原后的库会重放旧库的帧。

## 5. 可见性

恢复意味着**用户看到的数据比实际拥有的少**。静默恢复等于静默丢数据，而
`docs/01 §1.5` 把静默丢数据列为缺陷。

因此三层可见：

1. `Store.RecoveredFrom()` 返回被还原的备份路径；
2. Observer breadcrumb `storage.open.recovered_from_backup`；
3. `DiagnosticsDTO.RecoveredFromBackup`（文件名，未恢复为空）经绑定暴露给前端。

**已知缺口**：诊断界面尚未渲染该字段，前端显示待 preferences 接入。

## 6. 边界与已知空白

- **备份是时间点快照，恢复必然丢失备份之后的写入。** 这是备份的语义，无法回避；
  可见性（§5）是唯一补偿。
- **不做完整性预检。** 打开时跑 `PRAGMA integrity_check` 能多捕获一类「能打开但已损坏」的库，
  代价是每次启动全库扫描。实测截断到 1/3 的库会让连接直接失败，已覆盖 DB-7 场景；
  更隐蔽的损坏留待出现真实案例再决定。
- **恢复只在打开时发生。** 运行中途才暴露的损坏不触发还原——此时连接已在使用，
  其他实例可能也在读。

## 7. 回退

停用自动恢复只需让 `Open` 不再调用 `recoverFromNewestBackup`；`RestoreFromBackup` 与
`preservedPath` 保持可用，手动恢复走同一条已验证路径。**不得**改成删除原库，
也不得在环境故障上触发恢复。
