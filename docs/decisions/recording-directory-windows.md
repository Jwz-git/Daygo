# Windows 录制目录迁移

> 状态：Windows 实现已落盘，真实录制跨盘迁移仍待真机验收。macOS 继续使用固定录制目录。

## 决定

Windows 设置页允许用户选择一个空目录，将完整的 `recordings/` 树迁移过去。数据库、备份、密钥和实例锁仍位于 Daygo 应用数据目录。数据库中的 `segment_path` 保持相对录制根目录的路径，因此历史截图索引不改写。

有效目录存入 `app_settings.storage.recordingsDirectory`。未设置时使用应用数据目录下的 `recordings/`。迁移中间状态存入 `app_settings.storage.recordingsMigration`；设置和已提交状态在同一事务中写入。目标目录不能与源目录互相包含，也不能覆盖非空目录。

## 迁移与恢复

1. 只有写入与捕获所有者可以迁移。应用锁住捕获操作、回放、备份和录制定期清理，等待活跃录制分段收尾。
2. 将 `copying` 意图写入数据库，再把源目录的普通文件逐个复制到目标目录，按 SHA-256 校验。事务不跨文件 I/O。
3. 在应用数据目录写入 `recordings-location.guard`，然后以一个设置事务提交目标目录与 `committed` 状态。提交前源目录始终有效；提交后目标目录始终有效。
4. 校验目标副本后逐文件删除源文件。清理中断时，下次启动继续。复制中断时，原目录继续有效，用户可从设置页重试同一目标。

`recordings-location.guard` 阻止自动恢复一个早于最近目录迁移的数据库备份；那种备份仍指向已清理的旧录制目录。需要人工恢复时必须同时核对媒体位置。这个文件仅作恢复门禁，生效目录仍以数据库设置为准。

自定义目录在启动时不可用，应用跳过截图对账和分析启动，避免把缺失文件误判为损坏；定期清理跳过该目录。启动录制也要求自定义目录真实存在。恢复磁盘连接后需要重启应用，才能恢复启动时跳过的分析调度。

## 边界

- 第一版需要选择空目录；不会合并两处历史文件。当前界面显示复制和校验中的等待状态，可取消，未提供逐字节进度。
- 显式取消会放弃迁移意图，源目录继续生效；目标目录可能留有部分副本，应用不会自动删除用户选择的目录。崩溃中断的复制意图保留，可继续同一目标。
- 迁移时保留录制的启停与用户暂停状态。定时暂停沿用原到期时间；若迁移期间到期，迁移完成后恢复捕获。
- 跨磁盘复制期间源文件保留；清理失败会留下旧副本，下一次启动重试。
- macOS 不提供该设置入口，也不读取这个自定义目录键。

验证：匿名迁移与中断重试夹具、Windows 绑定所有权夹具、Go 存储 / 录制 / app 测试和前端构建。真实 Windows 分段收尾、跨盘、拔盘与重启仍须按 recording / data 门禁复核。
