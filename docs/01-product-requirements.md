# 01 产品需求

> 本文定义 Daygo 做什么、不做什么。它是范围争议的仲裁依据：任何"顺手加一个功能"的
> 提议，先回到这里确认它属于哪一节。

各需求按 [09 §9.7](09-roadmap.md#97-需求接口与测试归属) 分配给用户功能模块，
模块可并行推进；本文件继续作为产品范围依据，不因执行方式变化而增删需求。

## 1.1 问题陈述

知识工作者在一天结束时通常无法准确回答"我今天做了什么"。现有工具解决不了这个问题：

- **手动计时器**（Toggl 一类）要求用户记得启停，而人恰恰在专注时最不可能记得。
- **应用级时间统计**（Screen Time 一类）只知道哪个应用在前台，不知道你在那个应用里
  *做了什么*。"VS Code 3 小时"对复盘几乎没有信息量。
- **日历**记录的是计划，不是实际发生的事。

Daygo 的目标是保留**工作本身的上下文**：在构建什么、排查什么、和谁讨论什么、评审什么。

## 1.2 目标用户

主要用户是**需要向他人汇报工作、且工作内容高度碎片化的个人开发者与知识工作者**：

- 每天要写站会内容，但回忆昨天很费力；
- 同时在多个项目/分支/工单之间切换，事后难以还原时间去向；
- 对隐私敏感，不接受屏幕内容被上传到不受控的服务。

非目标用户：团队监控场景。Daygo **不提供**任何让第三方查看他人活动的能力，这是产品
边界，不是尚未实现的功能。

## 1.3 核心用户故事

| # | 作为用户，我希望 | 以便 |
|---|-----------------|------|
| U1 | 打开应用就能看到今天的活动时间线，不需要事先做任何配置动作 | 不必为了记录而中断工作 |
| U2 | 时间线上的每一段有标题、摘要和分类 | 一眼看出这段时间在做什么 |
| U3 | 纠正被分错类的时间段 | 分类体系符合我自己的工作划分 |
| U4 | 得到一份可直接粘贴的每日摘要 | 写站会不用回忆 |
| U5 | 看到本周各类工作的时间占比 | 判断时间是否花在了该花的地方 |
| U6 | 指定哪些应用永远不被截图 | 密码管理器、私人聊天不进入记录 |
| U7 | 自己选择用哪个 AI 服务、填自己的密钥 | 数据流向由我决定 |
| U8 | 关掉窗口后记录继续，需要时从状态栏叫回来 | 应用不占用屏幕空间 |
| U9 | 设定磁盘占用上限，旧录制自动清理 | 不会某天发现硬盘被占满 |
| U10 | 随时暂停记录，并且暂停会自动到期 | 开会或结对时临时关掉，事后不会忘记打开 |

## 1.4 功能需求

### 1.4.1 捕获

> F-C1 曾写成“跟随光标的活跃显示器”。原生契约冻结时把它改成了**系统主显示器**：
> 跟随光标需要显示器枚举、滞后判定和跨调用状态，而截图原语被有意设计成无状态的单次调用
> （[决策](decisions/recording-screen-capture.md#1-决定)）。对单显示器用户没有区别；
> 多显示器用户在 v1 只会记录到主显示器。是否恢复跟随行为是一个**待决产品问题**（§1.7），
> 不是实现遗漏。

| ID | 需求 | 验收标准 |
|----|------|----------|
| F-C1 | 按固定间隔截取**一块**显示器，v1 取调用时的**系统主显示器** | 多显示器下只产生一路记录；用户在系统设置里换主显示器后，下一次捕获自动跟随 |
| F-C2 | 间隔可配置 | 取值 1 / 5 / 10 / 20 / 30 / 60 秒，默认 10 秒 |
| F-C3 | 捕获分辨率可配置 | 720 / 1080 px 高度，默认 1080 |
| F-C4 | ABI 原子 JPEG 只作短期 staging；长期像素写入**不可变分段文件**，不写 SQLite BLOB | 完整分段发布后，单帧可通过 `(分段路径, 帧序号)` 随机访问；见[图片存储决策](decisions/recording-image-storage.md) |
| F-C5 | 前台应用在屏蔽名单内时，写入脱敏占位帧而不是跳过 | 时间线上仍能看到"这段时间有活动"，但没有内容 |
| F-C6 | 睡眠、锁屏、屏保期间停止捕获，事件结束后自动恢复 | 恢复是自动的，不需要用户干预 |
| F-C7 | 用户主动关闭记录后，系统事件**不得**自动恢复它 | `idle`（用户关闭）与 `paused`（系统事件）是不同状态 |
| F-C8 | 定时暂停 | 15 / 30 / 60 分钟或无限期；定时暂停到期自动恢复 |
| F-C9 | 缺少屏幕录制授权时停止捕获并显式提示 | 不静默失败；用户保存的"希望录制"偏好不被授权撤销覆盖 |

### 1.4.2 分析

| ID | 需求 | 验收标准 |
|----|------|----------|
| F-A1 | 帧按时间分批送 LLM，产出转录与活动卡片 | 目标批次 15 分钟；规则见 [04 §4.3](04-data-flow.md#43-分析流水线) |
| F-A2 | 整批空闲时**跳过 LLM**，直接写空闲卡片 | 判定为纯函数，阈值见 [04 §4.4](04-data-flow.md#44-空闲判定) |
| F-A3 | 主 provider 失败时回退到备用 provider | 回退具有粘性：同一批次切换后不回切 |
| F-A4 | 每次 provider 调用留审计记录 | 含尝试次数、provider、模型、耗时、截断正文 |
| F-A5 | 失败批次可重试，某一天可整体重处理 | 重处理不产生重复卡片 |
| F-A6 | 分析失败在 UI 上可见且可操作 | 不是静默留白 |

### 1.4.3 呈现

| ID | 需求 | 验收标准 |
|----|------|----------|
| F-V1 | 按逻辑日展示时间线，含标题、摘要、分类、时长 | 逻辑日边界为凌晨 4 点 |
| F-V2 | 卡片可展开查看该时段的帧条 | 帧按需解码，不阻塞列表渲染 |
| F-V3 | 可修改卡片的分类与标题，可删除卡片 | 删除是软删除 |
| F-V4 | 每日摘要：亮点、完成项、阻塞项 | 按**日历日**聚合（与时间线的逻辑日不同，见 [03 §3.2](03-data-model.md#32-凌晨-4-点逻辑日)） |
| F-V5 | 每周视图：跟踪时长、专注时长、分类占比 | 合计一律排除 `System` 分类 |
| F-V6 | 全部界面文案经 i18n，支持简体中文与英文 | 缺 key 在类型检查阶段失败，不在运行时回退 |
| F-V7 | 浅色 / 深色 / 跟随系统三态主题 | 跟随系统时随系统切换实时生效 |

### 1.4.4 设置

| ID | 需求 | 验收标准 |
|----|------|----------|
| F-S1 | 自定义 provider：名称、协议、接口地址、模型、密钥 | 协议 v1 支持 `openai`（Chat Completions）、`openai_responses`、`anthropic`（Messages）三种 |
| F-S2 | 主 / 备用 provider 路由 | 备用为空时表示不回退；备用不得与主相同 |
| F-S3 | 密钥写入系统钥匙串，**只写不读** | 任何接口都不返回密钥内容；UI 只知道"是否已配置" |
| F-S4 | provider 连接测试 | 一次真实调用，返回结果不回显密钥或完整请求体 |
| F-S5 | 屏蔽应用名单 | 按 bundle identifier |
| F-S6 | 录制磁盘占用上限 | 超限按**整个分段**清理最旧数据 |
| F-S7 | 分类体系可增删改、可调顺序与颜色 | 分类名称是卡片的外键语义，重命名需要同步已有卡片 |
| F-S8 | 开机自启、Dock 图标显隐 | |
| F-S9 | 遥测与崩溃上报默认关闭 | opt-in，且不含任何屏幕内容 |

### 1.4.5 生命周期

| ID | 需求 | 验收标准 |
|----|------|----------|
| F-L1 | 关闭窗口后进程继续运行并继续捕获 | |
| F-L2 | 状态栏可重新打开窗口、快速暂停、查看状态 | |
| F-L3 | Cmd+Q、窗口关闭、更新重启、系统关机是四个不同事件 | 每个都必须完成或安全移交当前分段 |
| F-L4 | 自动更新 | 实现**待定设计**；更新重启不得丢失未收尾的分段 |

## 1.5 非功能需求

| 类别 | 要求 |
|------|------|
| 隐私 | 见 [07](07-privacy-security.md)。屏幕数据只发往用户明确配置的 provider；屏蔽名单与脱敏占位帧两层保护都必须存在 |
| 资源占用 | 空闲态 CPU 占用不应稳定高于个位数百分比；捕获间隔 10 秒时不应产生可感知的输入延迟 |
| 数据安全 | 单一写入方；异常退出不得损坏数据库；未收尾的分段必须可恢复或被安全丢弃 |
| 可观测性 | 静默丢数据是缺陷。解析失败、跳过的卡片、失败批次都必须计数并可在诊断界面看到 |
| 可测试性 | Go Core 必须能在无 macOS、无 GUI 的环境中构建与测试（`CGO_ENABLED=0`） |
| 国际化 | 全部用户可见文案经 i18n；后端错误 `message` 不本地化，前端按错误码映射文案 |

## 1.6 明确的非目标

以下不是"以后再做"，而是**不做**：

- **团队/管理视角。** 不提供他人活动的查看、汇总或导出能力。
- **持续屏幕录像。** 采用离散截图而非连续视频流，这样系统的屏幕录制指示器不会常亮。
  这是产品决策，不是性能优化。
- **键盘输入记录。** 不记录击键、剪贴板内容或窗口标题文本。
- **云端账号体系。** v1 无登录、无同步、无服务端。
- **自动向第三方汇报。** 不集成日报机器人、工单系统写回。
