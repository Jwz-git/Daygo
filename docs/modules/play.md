## 用户结果与范围

一句话：**每周一座新岛；当天在电脑前度过的时间会变成一叠地形方块，把它们拼到岛上，让同类地形连成片。**

用户打开「拼岛」页，看到本周的岛和一叠待放方块；方块随当天卡片生成陆续到达。用户每次选一块、旋转、放到
岛上已有方块旁边，相邻边地貌一致即得分；完成当日任务点亮当日徽记。每周一 4 点开新岛，旧岛封存进图册。

### 数据 → 方块（Go 侧确定性生成）

| 规则 | 内容 |
|---|---|
| 切片 | 逻辑日（4 点边界，`timeutil.DayWindow`）按 30 分钟切成 48 个时段（DST 日按实际长度）；时段内非 System、非 Idle 的卡片分钟 ≥ 10 才产出方块。卡片读取沿用 `CardsForDay` 与跨 4 点裁剪规则，前端不推算 |
| 身份 | 方块 ID = `(day, slotIndex)`，不用卡片 ID——自动改写 / 重处理会替换卡片，按时段寻址保持稳定 |
| 地貌 | 分类 → 地貌。初始分类默认：Focus Work→森林、Learning→湖泊、Research→山地、Communication→村庄、Personal→花田、Distraction→野地；自定义分类默认「草原」并以分类 `colorHex` 着色 |
| 四条边 | 按时段内各分类分钟占比分配，主分类至少 2 条。整块专注 = 四边同地貌，最易拼；频繁切换 = 混合边，更难拼 |
| 时长挂钩（软上限） | 每天前 16 个有效时段 1:1 发放；之后每 2 个时段 1 块；单日上限 24 块。无数据日保底 4 块通用「晨雾」方块 |
| 特殊地标 | 只看结构、不看时长：计划块完成→风车；当日专注目标达成→灯塔；日记完成→许愿树；单次连续专注 ≥ 90 分钟→山峰；两段工作间休息 ≥ 30 分钟→温泉 |

### 每日一关

- 每天 2–3 个当日任务，由数据派生且**必须可达成**，例如「最大森林连片 ≥ N」（N = 当日森林块数 × 0.6 向上取整）、
  「把野地围起来」「风车与村庄相邻」。
- 计分：每条匹配边 +1；四边全匹配为「完美块」额外加分；完成任务加分。
- 方块随分析批次陆续到达，白天可多次回来放置；不依赖推送通知。

### 长期养成

- 每周一岛：本周任一天的未放置方块在本周内都可放，**错过一天不丢失**；不做连续天数。
- 周任务来自 `WeeklyInsightsDTO`（最长专注、活跃天数、高峰时段）。
- 周结束封存为岛屿缩略图进入图册；地标与特殊地貌进入图鉴。

### 数据变动规则

- 已放置方块是快照（保存边与地貌），之后卡片编辑 / 重处理 / 分类改名都不改变它。
- 未放置方块每次读取按当前卡片重算；时段数据被删除则该未放置方块消失。

### 二期（可选）：今日拼图

把当日 15 分钟工作流网格压缩成 5×5 / 6×6 的已解布局，挖掉 k 块并打乱旋转交给用户复原；由构造保证必有解，
接受任意满足全部边的摆法，完成后揭示「你的一天」图样。是否做见待决项。

### 非目标（一期）

货币、商店、体力、广告；连续天数 / 断签提示；排行榜与社交；LLM 生成文案或关卡；
经 CLI / MCP / agent.sock / chat 操作游戏；云同步。

## 能力与跨层职责

| 输入能力 / 契约 | 负责模块 | 可独立推进 / fake 可证明什么 | 真实接入前置条件 |

| 当日卡片与分类 | timeline | `CardsForDay`、`Categories().List` 读路径；匿名卡片夹具可证明切片与边分配 | 无新增 |
| 计划完成、专注目标、日记状态 | plan / daily | `GetPlanDay`、`GetDayGoal`、`GetJournalDay` 背后的 service 读路径；夹具证明地标发放 | 无新增 |
| 周洞察 | weekly | `GetWeeklyDashboard` 的 `WeeklyInsightsDTO`；夹具证明周任务派生 | 无新增 |
| 游戏状态持久化 | data（schema 机制）/ play（表与 repository） | 新迁移 + 旧库夹具 | 迁移链与 `internal/storage` 唯一 SQL 约束 |
| `play.enabled` 设置 | preferences（访问）/ play（字段） | 按 `llm.showTokenUsage` 的接入路径 | 默认值待决 |

技术层职责（规划）：

- `internal/play`：纯函数——方块生成、任务派生、落子合法性、计分。不依赖 Wails、不含 SQL。
- `internal/storage/play.go`：岛屿与落子 repository；schema 变更走版本化迁移（当前最新 v23，新增应为 v24 起）。
- `internal/app`：绑定与 DTO（草案 `GetPlayWeek(weekStart)`、`PlacePlayTile(...)`、事件 `play:updated`），
  只读实例写方法返回 `not_capture_owner`，游戏降级为只看。契约落地前须先写入 05。
- 前端：`views/Play/`、`stores/play.ts`、`api/play.ts`；SVG 方格 + CSS 过渡，不新增依赖；写后等事件重拉；
  新 i18n 命名空间 `play` 九语言；游戏状态不进 localStorage。
- 隐私：纯本地，不调用 LLM、不联网、不上报，不展示卡片之外的新信息。

## 实验与失败条件

| 实验 / 风险 | 输入与操作 | 预期结果 | 失败条件 / 证据 |
|---|---|---|---|
| PL-1 奖励过劳 | 匿名夹具：8 h 与 12 h 工作日 | 方块数差 ≤ 4；任何日 ≤ 24 | 超出则重新设计发放规则并更新决策记录 |
| PL-2 低数据日 | 0 张卡片；仅 1 张 15 分钟卡片 | 保底 4 块，当日任务全部可达成 | 任一任务不可达成 |
| PL-3 重处理稳定 | 同一时段卡片被改写替换 ID | slot ID 不变；已放置快照不变；未放置方块按新卡片重算 | 方块漂移或已放置方块改变 |
| PL-4 跨 4 点 / DST | 复用 timeutil 夹具：跨 4 点卡片、DST 前进 / 回退日、半小时与 45 分钟时区 | 方块归属正确逻辑日；时段数与日长一致 | 归属错误或时段缺失 / 重复 |
| PL-5 任务可达成 | 属性测试：随机匿名日数据 | 每个生成的任务至少存在一种达成摆法（或由构造保证） | 出现不可达任务 |
| PL-6 确定性 | 同一输入重复生成 | 方块、边、任务逐字节一致 | 任何非确定性 |
| PL-7 分心表达 | 九语言文案评审 | 无负面评价措辞；野地有正向玩法 | 出现羞辱性表达 |

## 实现切片与集成

4. **绑定与事件**：DTO、绑定、`play:updated`、只读降级；同步 05，双侧契约测试。
5. **store 与 UI**：页面、侧栏入口、空态 / 加载 / 错误态、九语言、设置开关。
6. **真实闭环**：真实卡片日在 macOS 上从录制到放置的用户闭环；一周跨周封存观察单独记录。
